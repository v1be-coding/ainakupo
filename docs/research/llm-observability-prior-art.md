# LLM observability prior art (for the AInakupo spec)

Researched 2026-11-19 against primary sources: official docs, vendor source on GitHub, and the OpenTelemetry
GenAI semantic conventions repo. Where a source did not answer a question, the cell says **not confirmed**
rather than guessing. Vendor docs change fast. Langfuse removed its legacy ingestion API three days before
this was written, for example. Re-check anything a frozen test will depend on.

Tools covered: Langfuse, Helicone, LangSmith, Arize Phoenix (with its OpenInference conventions),
OpenLLMetry (Traceloop) and the OTel GenAI semantic conventions, Braintrust, Lunary.

---

## 1. Summary: the industry norms

- **Nested spans are the norm.** Every tool except Helicone's proxy logs models a *trace* as a tree of
  spans (Langfuse "observations", LangSmith "runs", Braintrust "spans"). One LLM call is one leaf span of
  type `llm`/`generation`. A flat "one trace = one call" model is unusual, but it's a clean subset: each
  record is a root span with no children.
- **OpenTelemetry is becoming the ingest format.** Langfuse now accepts traces *only* over OTLP on Cloud
  (as of 2026-11-16). Phoenix, OpenLLMetry and Braintrust also accept OTLP, and LangSmith documents an OTel
  path too. The OTel GenAI conventions (`gen_ai.*`, still status *Development*) are the shared vocabulary.
- **Cost is mostly computed server-side** from a regex-matched model price table (Langfuse, LangSmith,
  Phoenix, Helicone, Braintrust, Lunary). Most of these also accept a client-sent cost. Langfuse says
  client-sent cost wins. For unknown models the norm is "no cost": none of them guess.
- **The OTel spec says content capture should be opt-in.** Vendor SDKs mostly capture prompt and response
  text by default anyway (OpenLLMetry, Phoenix/OpenInference, LangSmith, Helicone), and they offer hide or
  mask hooks instead.
- **Keys are scoped to a project.** Langfuse uses a public+secret pair. LangSmith offers write-only
  "tracing keys". Lunary splits a public ingest key from a private read key. Langfuse stores only hashes
  of secret keys.
- **Ingest rate limits are per organisation and generous** (thousands of requests per minute). Self-hosted
  Langfuse and Phoenix enforce none.
- **Every SDK batches in the background and needs an explicit flush on Lambda.** Langfuse uses
  `shutdown()`, LangSmith `awaitPendingTraceBatches()`, Braintrust `asyncFlush:false` plus `flush()`,
  Phoenix `shutdown()` or `batch:false`.
- **LLM-as-judge is mostly rule-driven:** filters plus a sampling rate on incoming traces, with backfill or
  manual "evaluate these rows" (Langfuse, LangSmith, Braintrust). Helicone and Phoenix leave judging to
  the user's code and only store the scores.
- **The common score shape** is a name, a numeric value (often 0–1), an optional categorical label, and a
  free-text reasoning/comment. OTel's `gen_ai.evaluation.result` event encodes exactly that.
- **IDs are generated by the client.** OTel span IDs are client-side by construction. LangSmith recommends
  client UUIDv7 run IDs. Braintrust accepts a client `id` and replaces or merges on conflict. Helicone lets
  you predefine `Helicone-Request-Id`. Langfuse scores take an `id` as an idempotency key.

## 2. Data model

| Tool | Unit of storage | What a "trace" is | LLM-call fields (tokens / model / latency / cost) | User / session / metadata |
|---|---|---|---|---|
| **Langfuse** | *Observations* (span, generation, event, and other LLM types), nestable ([data model](https://langfuse.com/docs/observability/data-model)) | "a single request or operation": the observations that share a `trace_id`. Trace attributes are copied onto every observation row ([data model](https://langfuse.com/docs/observability/data-model)) | Generations carry model plus usage and cost details. Over OTLP they map from `gen_ai.request.model`, `gen_ai.usage.*`, `gen_ai.usage.cost` or `langfuse.observation.cost_details` ([OTel mapping](https://langfuse.com/integrations/native/opentelemetry)) | `user_id`, `session_id`, tags, metadata, environment, release ([data model](https://langfuse.com/docs/observability/data-model)). Sessions group traces |
| **Helicone** | One logged *request* (provider request plus response) ([manual logger](https://docs.helicone.ai/getting-started/integration-method/manual-logger-curl.md)) | No span tree. "Sessions" group requests through `Helicone-Session-Id` and `Helicone-Session-Path` path syntax ([headers](https://docs.helicone.ai/helicone-headers/header-directory.md)) | Parsed from the provider response body. Optional `timing.startTime`/`endTime`/`timeToFirstToken`, which default to "now" if omitted ([manual logger](https://docs.helicone.ai/getting-started/integration-method/manual-logger-curl.md)) | `Helicone-User-Id`, `Helicone-Property-*` custom properties ([headers](https://docs.helicone.ai/helicone-headers/header-directory.md)) |
| **LangSmith** | *Runs* (`run_type`: chain, llm, embedding, prompt, tool, retriever, parser) ([run format](https://docs.langchain.com/langsmith/run-data-format)) | Root run plus descendants. `trace_id` equals the root run's `id`. `dotted_order` encodes the position in the tree ([run format](https://docs.langchain.com/langsmith/run-data-format)) | `prompt_tokens`, `completion_tokens`, `total_tokens`, `prompt_cost`, `completion_cost`, `total_cost`, `start_time`/`end_time`, `first_token_time` ([run format](https://docs.langchain.com/langsmith/run-data-format)). Model comes from `ls_model_name`/`ls_provider` metadata ([cost tracking](https://docs.langchain.com/langsmith/cost-tracking)) | `extra` (metadata), tags. `session_id` here means the *project*, not a user session ([run format](https://docs.langchain.com/langsmith/run-data-format)) |
| **Phoenix / OpenInference** | OTel spans with a required `openinference.span.kind` (LLM, EMBEDDING, CHAIN, RETRIEVER, RERANKER, TOOL, AGENT, GUARDRAIL, EVALUATOR, PROMPT, DECISION) ([OpenInference attrs](https://github.com/Arize-ai/openinference/blob/main/spec/attributes/semantic-conventions.md)) | Standard OTel trace | `llm.model_name`, `llm.provider`, `llm.token_count.prompt`/`completion`/`total`, optional `llm.cost.total`/`llm.cost.prompt` (USD) ([OpenInference attrs](https://github.com/Arize-ai/openinference/blob/main/spec/attributes/semantic-conventions.md)). Latency is the span duration | `session.id`, `user.id`, metadata ([OpenInference context](https://github.com/Arize-ai/openinference/blob/main/spec/attributes/context.md)) |
| **OTel GenAI semconv** | Span `gen_ai.client.inference`, named `{gen_ai.operation.name} {gen_ai.request.model}`, status *Development* ([client-inference](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)) | Standard OTel trace. One client request "may involve multiple server-side inference operations" ([client-inference](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)) | **Required:** `gen_ai.operation.name`, `gen_ai.provider.name`. **Cond. required:** `gen_ai.request.model` (if available), `error.type` (on error). **Recommended:** `gen_ai.response.model`, `gen_ai.response.id`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, cache and reasoning token counts, `gen_ai.response.finish_reasons`. **No cost attribute.** Duration comes from the span or the `gen_ai.client.inference.duration` metric in seconds ([client-inference](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)) | `gen_ai.conversation.id`, set only when one already exists. It "SHOULD NOT" be a fresh UUID or trace id ([client-inference](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)) |
| **Braintrust** | Log events/spans with `span_attributes.type` (llm, score, function, eval, task, tool, …) ([insert logs](https://docs.braintrust.dev/api-reference/logs/insert-project-logs-events)) | Spans that share `root_span_id`, linked by `span_parents` ([insert logs](https://docs.braintrust.dev/api-reference/logs/insert-project-logs-events)) | `metrics.start`, `metrics.end` (unix timestamps), `prompt_tokens`, `completion_tokens`, `tokens`. The insert schema has **no cost field** ([insert logs](https://docs.braintrust.dev/api-reference/logs/insert-project-logs-events)). Model goes in `metadata.model` ([cost preset](https://docs.braintrust.dev/kb/total-llm-cost-preset-requirements.md)) | `metadata` (string keys, any JSON), `tags`, `scores` ([insert logs](https://docs.braintrust.dev/api-reference/logs/insert-project-logs-events)) |
| **Lunary** | Run *events* with `type` (llm, chain, agent, tool, log, embed, retriever, chat, convo, message, thread) and `event` (start/end) ([ingest](https://docs.lunary.ai/api/runs/ingest-run-events.md)) | Runs linked by `parentRunId` | `name` (model), `tokensUsage.prompt`/`completion`, `timestamp`. Latency comes from the start and end events. No cost field in the schema ([ingest](https://docs.lunary.ai/api/runs/ingest-run-events.md)) | `metadata`. `userId` is not in the documented schema (`additionalProperties: true`) ([ingest](https://docs.lunary.ai/api/runs/ingest-run-events.md)) |

**Takeaways.**
- Required fields are thin everywhere. OTel requires only the operation and provider names. Tokens, model
  and response id are "recommended".
- Latency is almost never a field. It's derived from start and end times, or from the span duration.
- The `input_tokens`/`output_tokens` naming (OTel, Langfuse's OTel mapping) has replaced the older
  `prompt_tokens`/`completion_tokens` (LangSmith, Braintrust, OpenInference).

## 3. Ingest auth and rate limits

| Tool | Credential | Scope and storage | Ingest rate limits |
|---|---|---|---|
| **Langfuse** | Public key plus secret key over HTTP Basic auth (`pk-lf-…:sk-lf-…`), used on the Public API and the OTLP endpoint ([public API](https://langfuse.com/docs/api-and-data-platform/features/public-api), [OTel](https://langfuse.com/integrations/native/opentelemetry)). The browser SDK uses the public key alone and can only send scores, not traces ([SDK overview](https://langfuse.com/docs/observability/sdk/overview)) | Scoped to a project by default (`scope @default(PROJECT)`). The DB stores `publicKey`, `hashedSecretKey` (bcrypt for older keys), `fastHashedSecretKey` and a `displaySecretKey`, never the plaintext secret ([prisma schema](https://raw.githubusercontent.com/langfuse/langfuse/main/packages/shared/prisma/schema.prisma)) | Per **organisation**, shared across projects and keys: Hobby 1,000, Core 4,000, Pro+ 20,000 req/min on `/ingestion` and `/otel`. 5 MB per request. 429 with `Retry-After`. Self-hosted: no limits ([API limits](https://langfuse.com/faq/all/api-limits)) |
| **Helicone** | One Helicone API key as `Authorization: Bearer` ([quick start](https://docs.helicone.ai/getting-started/quick-start), [manual logger](https://docs.helicone.ai/getting-started/integration-method/manual-logger-curl.md)) | Key storage: **not confirmed** | Ingest limits **not confirmed**. `Helicone-RateLimit-Policy` limits *your LLM traffic* through the proxy, not logging ([headers](https://docs.helicone.ai/helicone-headers/header-directory.md)) |
| **LangSmith** | `x-api-key` header, plus `x-tenant-id` for multi-workspace keys ([trace with API](https://docs.langchain.com/langsmith/trace-with-api)). Key types: personal access tokens, service keys, and **tracing keys** limited to `runs:create` and `projects:create` ([API keys](https://docs.langchain.com/langsmith/create-account-api-key)) | Workspace- or org-scoped ([API keys](https://docs.langchain.com/langsmith/create-account-api-key)). Storage **not confirmed** | 5,000 req/min on `POST/PATCH /runs*`. Hourly events 50k–500k by plan. Hourly data 500 MB–5 GB by plan ([usage & billing](https://docs.langchain.com/langsmith/usage-and-billing)) |
| **Phoenix** | Auth is **off by default**. With `PHOENIX_ENABLE_AUTH=True`, senders use `Authorization: Bearer <key>`. *System* keys (admin-created, for automated ingest) and *user* keys ([auth](https://arize.com/docs/phoenix/self-hosting/features/authentication)) | API-key storage **not confirmed**. Passwords are stored salted and hashed ([auth](https://arize.com/docs/phoenix/self-hosting/features/authentication)) | Not documented for self-host (**not confirmed**) |
| **OpenLLMetry** | `TRACELOOP_API_KEY`, or arbitrary `TRACELOOP_HEADERS`, which then override the key ([config](https://www.traceloop.com/docs/openllmetry/configuration)) | Set by whichever backend receives the OTLP data | Set by the backend |
| **Braintrust** | `Authorization: Bearer <api_key>` ([insert logs](https://docs.braintrust.dev/api-reference/logs/insert-project-logs-events)). Service tokens can be scoped for log ingestion ([llms.txt index](https://docs.braintrust.dev/llms.txt)) | Storage **not confirmed** | Exact numbers **not confirmed**. KB pages mention rate limits during backfill and OTLP payload limits ([llms.txt index](https://docs.braintrust.dev/llms.txt)) |
| **Lunary** | Project key as a Bearer token. The ingest endpoint accepts the **public** key (`ProjectPublicApiKeyAuth`). Reads, exports and eval runs need the **private** key ([ingest](https://docs.lunary.ai/api/runs/ingest-run-events.md), [run eval](https://docs.lunary.ai/api/evals/run-the-evaluation.md)) | Project-scoped. Storage **not confirmed** | **Not confirmed** |

**Takeaways.**
- Write-only ingest credentials are an established pattern: LangSmith tracing keys and Lunary public keys.
- Langfuse's pair is not a write-only split. Both halves are needed for server ingest, and the public half
  alone is for browser score submission.
- Hash-at-rest is confirmed only for Langfuse.
- No tool documented a *per-key* ingest limit. Limits are per organisation or per plan.

## 4. Cost

| Tool | Default method | Client-sent cost? | Unknown model |
|---|---|---|---|
| **Langfuse** | Inferred at ingestion: the generation's `model` is matched against regex `match_pattern` model definitions, then multiplied by per-usage-type prices. Defaults ship for OpenAI, Anthropic and Google. User definitions override them ([cost](https://langfuse.com/docs/observability/features/token-and-cost-tracking)) | **Yes, and it wins:** "ingested costs take priority over inferred ones" ([cost](https://langfuse.com/docs/observability/features/token-and-cost-tracking)). Over OTLP: `gen_ai.usage.cost` or `langfuse.observation.cost_details` ([OTel](https://langfuse.com/integrations/native/opentelemetry)) | No cost unless one was ingested. Langfuse no longer estimates tokens from text: "If neither usage nor cost is submitted, no cost is calculated." Price changes are not backfilled ([cost](https://langfuse.com/docs/observability/features/token-and-cost-tracking)) |
| **Helicone** | Server-side, from an open-source cost repo of 300+ models, or "Model Registry v2" via its AI Gateway ([cost tracking](https://docs.helicone.ai/guides/cookbooks/cost-tracking.md), [how we calculate](https://docs.helicone.ai/references/how-we-calculate-cost)) | Not documented. The only lever is `Helicone-Model-Override`, which "overrides the model used to calculate costs" ([headers](https://docs.helicone.ai/helicone-headers/header-directory.md)) | No cost is shown. The fix is to ask Helicone to add the model ([cost tracking](https://docs.helicone.ai/guides/cookbooks/cost-tracking.md)) |
| **LangSmith** | Pricing map that regex-matches `ls_model_name` (and optionally `ls_provider`), with token-type-specific prices ([cost](https://docs.langchain.com/langsmith/cost-tracking)) | **Yes:** `input_cost`/`output_cost`/`total_cost` in `usage_metadata`, recommended "for any other model with non-linear pricing" ([cost](https://docs.langchain.com/langsmith/cost-tracking)) | **Not confirmed**. You add a pricing entry. Map changes are not backfilled ([cost](https://docs.langchain.com/langsmith/cost-tracking)) |
| **Phoenix** | Computed "when a span is ingested" from token counts and a pricing table matched on `llm.model_name`/`llm.provider`. Custom regex entries override built-ins ([cost](https://arize.com/docs/phoenix/tracing/how-to-tracing/cost-tracking)) | OpenInference *defines* `llm.cost.*` USD attributes ([attrs](https://github.com/Arize-ai/openinference/blob/main/spec/attributes/semantic-conventions.md)). Whether Phoenix prefers them over its table is **not confirmed** | **Not confirmed**. You add a custom model ([cost](https://arize.com/docs/phoenix/tracing/how-to-tracing/cost-tracking)) |
| **OTel semconv** | No cost attribute exists. Token metrics are described as "a proxy for cost approximation" ([token metrics](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-token-metrics.md)) | n/a | n/a |
| **Braintrust** | Preset charts price spans from `metadata.model` and token metrics against Braintrust's pricing registry ([cost preset](https://docs.braintrust.dev/kb/total-llm-cost-preset-requirements.md)) | Partly. `metrics.estimated_cost` is used by custom charts through `estimated_cost()` but **ignored by the preset** ([cost preset](https://docs.braintrust.dev/kb/total-llm-cost-preset-requirements.md)) | The preset drops spans with a null, missing or unrecognised model ([cost preset](https://docs.braintrust.dev/kb/total-llm-cost-preset-requirements.md)) |
| **Lunary** | A model table with `pattern`, `unit` (TOKENS/CHARACTERS/MILLISECONDS), `inputCost`, `outputCost`, `tokenizer`, `startDate` ([models API](https://docs.lunary.ai/api/models/create-a-new-model.md)). Server-side computation is implied but **not stated** | **Not confirmed** | **Not confirmed** |

**Takeaways.**
- Server-side tables are the norm, and every vendor keeps one: regex match, per-token-type prices,
  user overrides, no backfill.
- Client-sent cost is accepted widely as an override.
- Langfuse and LangSmith both recommend client-side cost for anything with non-linear pricing, such as
  cached tokens or thinking models.

## 5. Prompt/response capture

| Tool | Default | Opt-out, redaction | Size limits |
|---|---|---|---|
| **OTel semconv** | **Off.** Instrumentations "SHOULD NOT capture them by default, but SHOULD provide an option for users to opt in". `gen_ai.input.messages`, `gen_ai.output.messages` and `gen_ai.system_instructions` are `Opt-In` ([spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)) | A capture config is mandatory for instrumentations that support content, e.g. `OTEL_INSTRUMENTATION_GENAI_CAPTURE_CONTENT=EVENT_ONLY` or `SPAN_AND_EVENT`. For production the spec recommends storing content externally and recording `*_ref` URIs on spans ([events](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-events.md), [spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)) | No fixed number. Instrumentations "MAY" truncate message contents "preserving JSON structure" ([spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)) |
| **OpenLLMetry** | **On:** "By default, OpenLLMetry logs prompts, completions, and embeddings to span attributes" ([privacy](https://www.traceloop.com/docs/openllmetry/privacy/traces)) | `TRACELOOP_TRACE_CONTENT=false` or `traceContent: false` ([privacy](https://www.traceloop.com/docs/openllmetry/privacy/traces)) | **Not confirmed** |
| **Phoenix / OpenInference** | **On.** All `OPENINFERENCE_HIDE_*` flags default to False ([masking](https://arize.com/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes)) | `OPENINFERENCE_HIDE_INPUTS`/`OUTPUTS`/`INPUT_MESSAGES`/…, or `TraceConfig` in code ([masking](https://arize.com/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes)) | Base64 images capped at 32,000 chars by default (`OPENINFERENCE_BASE64_IMAGE_MAX_LENGTH`) ([masking](https://arize.com/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes)). Text limits **not confirmed** |
| **LangSmith** | Implicitly on ([mask](https://docs.langchain.com/langsmith/mask-inputs-outputs)) | `LANGSMITH_HIDE_INPUTS`/`HIDE_OUTPUTS`, `hideInputs`/`hideOutputs` functions, regex `createAnonymizer` ([mask](https://docs.langchain.com/langsmith/mask-inputs-outputs)) | Per-run limit **not confirmed**. Hourly data caps apply ([usage](https://docs.langchain.com/langsmith/usage-and-billing)) |
| **Langfuse** | Default **not stated** in the docs. The SDKs record input and output on observations ([SDK overview](https://langfuse.com/docs/observability/sdk/overview)) | `mask` function on `LangfuseSpanProcessor` for input, output and metadata (JS). `mask_otel_spans` in Python. A failing Python mask "drops the whole export batch" ([masking](https://langfuse.com/docs/observability/features/masking)) | 5 MB per request ([API limits](https://langfuse.com/faq/all/api-limits)). Per-field limits **not confirmed** |
| **Helicone** | On. It's a proxy that sees full bodies ([omit headers](https://docs.helicone.ai/helicone-headers/header-directory.md)) | `Helicone-Omit-Request` / `Helicone-Omit-Response`. These are still *sent* to Helicone, just not stored ([omit logs](https://docs.helicone.ai/features/advanced-usage/omit-logs)) | **Not confirmed** |
| **Braintrust** | Logged whenever the record includes them ([redact](https://docs.braintrust.dev/sdks/typescript/redact-sensitive-data.md)) | `setMaskingFunction()`. It does not run on `metadata` or feedback comments ([redact](https://docs.braintrust.dev/sdks/typescript/redact-sensitive-data.md)) | **Not confirmed** |
| **Lunary** | `input`/`output` are ordinary event fields ([ingest](https://docs.lunary.ai/api/runs/ingest-run-events.md)) | **Not confirmed** | **Not confirmed** |

**Takeaways.**
- The spec says off by default. Vendors mostly ship capture on, because the dashboard is less useful
  without content.
- No vendor documented a per-field size cap like 8 KB. The limits found are request-level (Langfuse 5 MB)
  or image-specific (Phoenix 32k chars).
- Helicone shows a subtle point: an omit flag that still *transmits* the data is weaker than not sending
  it at all.

There's an optional Lambda extension for a local handoff ([TS install](https://docs.braintrust.dev/sdks/typescript/install-and-instrument.md), [Lambda](https://docs.braintrust.dev/integrations/runtime-environments/aws-lambda.md)) |
| **Lunary** | npm `lunary` ([JS install](https://docs.lunary.ai/integrations/javascript/installation.md)) | Lunary cloud (`api.lunary.ai` in API docs ([ingest](https://docs.lunary.ai/api/runs/ingest-run-events.md))) | `LUNARY_PUBLIC_KEY`, `LUNARY_API_URL` | SDK wrappers plus REST ingest | **Not confirmed** |

**Takeaways.**
- Every vendor publishes to npm or pypi and defaults to *its own cloud*. Phoenix, which defaults to
  localhost, is the exception.
- A "no default endpoint" SDK is unusual, but it's the safest choice for a self-hosted portfolio app: a
  misconfigured sender fails loudly instead of leaking data somewhere.
- Background batching plus a mandatory flush is the universal Lambda footgun.

## 9. AInakupo vs prior art

**1. One Trace = one model call, with no spans.**
- *Differs from the norm.* Every tool nests, and even OTel notes that one request can contain several
  inference operations.
- It's defensible for v1, because each AInakupo Trace is exactly one OTel `gen_ai.client.inference` span,
  or one Langfuse `generation`. The risk is vocabulary confusion: in every other tool, "trace" means the
  *group*.
- *Borrow:* keep the optional `runId` for grouping. Name it so it can later become a root/trace id. Don't
  call it `conversationId`, which OTel reserves for pre-existing conversation ids ([client-inference
  note 5](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)).
- Write in the GLOSSARY that an AInakupo Trace is what others call a generation or LLM span.

**2. Field names.** Not decided yet, so this is cheap to align.
- *Borrow:* use OTel GenAI names and meanings even in a plain JSON body: `provider`
  (`gen_ai.provider.name`, values like `anthropic`), `model` (`gen_ai.request.model`), `inputTokens` and
  `outputTokens` (`gen_ai.usage.*`), optional `responseId` and `errorType`.
- Pin the OTel definitions: input tokens *include* cached tokens, and output tokens *include* reasoning
  tokens ([client-inference notes
  28–29](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md)).
  Otherwise two apps will count Claude cache reads differently.
- Have the client send `startedAt` and `durationMs` rather than "latency" alone. Every tool derives latency
  from start and end times, and a start time also orders traces correctly when clients batch.
- Leave room for an OTLP endpoint later, but don't build it in v1. The semconv is still *Development*.

**3. Per-app ingest key, hash-only storage, missing or unknown key rejected.**
- *Matches the norm.* Keys are scoped to a project or app everywhere, and Langfuse stores only hashes
  ([schema](https://raw.githubusercontent.com/langfuse/langfuse/main/packages/shared/prisma/schema.prisma)).
- Write-only ingest credentials have precedent: LangSmith tracing keys and Lunary public ingest keys.
- *Borrow:* a recognisable prefix (Langfuse `pk-lf-`/`sk-lf-`), which helps secret scanners, plus a
  display-safe suffix for the dashboard (Langfuse `displaySecretKey`).
- *Skip* a public/secret pair. Langfuse's pair exists for browser score submission, and AInakupo has no
  browser senders.
- A fast hash like SHA-256 is fine for high-entropy random keys. Langfuse added `fastHashedSecretKey`
  alongside bcrypt for exactly that reason.

**4. Per-key rate limit of 60 traces per 60 s.**
- *Differs in grain and size.* Others limit per organisation and by requests, at thousands per minute
  ([Langfuse](https://langfuse.com/faq/all/api-limits), [LangSmith](https://docs.langchain.com/langsmith/usage-and-billing)).
- Per key is better for AInakupo, since one noisy app shouldn't starve the others. 60 per minute is low but
  suits small apps.
- *Borrow:* return 429 with `Retry-After`, as Langfuse does. Have the SDK drop the trace rather than retry
  in a loop inside a Lambda.
- Decide whether a retry that upserts an *existing* id counts against the limit. Not counting it makes
  client retries safe.

**5. Cost reported by the client (`costUsd`).**
- *Minority, but legitimate.* All the major tools keep server price tables. Langfuse and LangSmith also
  accept client cost, and Langfuse gives it precedence
  ([Langfuse](https://langfuse.com/docs/observability/features/token-and-cost-tracking),
  [LangSmith](https://docs.langchain.com/langsmith/cost-tracking)). OTel defines no cost attribute at all.
- Client cost avoids the hardest maintenance (price tables, cache and thinking pricing). Both vendors
  recommend client cost exactly for non-linear pricing.
- *Risks:* a wrong or zero cost silently skews totals, and no tool can recompute it. Mitigations:
  - make `costUsd` optional and nullable, and show "unknown" rather than 0, following Langfuse's "no cost
    rather than a guess";
  - validate it as non-negative and finite;
  - always store the token counts, so a server-side table can be added later.

**6. Prompt and response text off by default, stored only if sent, capped at 8 KB per field.**
- *Matches the OTel spec* ("SHOULD NOT capture … by default"). It's *stricter than most vendors*:
  OpenLLMetry, Phoenix and LangSmith capture by default
  ([OTel](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md),
  [OpenLLMetry](https://www.traceloop.com/docs/openllmetry/privacy/traces),
  [Phoenix](https://arize.com/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes)).
- Not sending is stronger than Helicone's omit header, which still transmits the data
  ([omit logs](https://docs.helicone.ai/features/advanced-usage/omit-logs)).
- No vendor documents a per-field cap, so 8 KB is our own choice. Spec it precisely:
  - whether 8 KB means bytes or characters, and UTF-8 bytes in particular;
  - whether oversized text is **rejected or truncated**. OTel suggests truncation is acceptable;
  - if it's truncated, store a `truncated: true` flag.
- *Important interaction with the judge (item 8):* a trace with no stored text can't be judged on
  content. The judge route needs a defined response for that case.

**7. TypeScript SDK installed from git, with no default endpoint and no API-key handling.**
- *Differs on distribution:* everyone else uses npm or pypi. *Differs on the default:* everyone else
  defaults to their cloud, except Phoenix (localhost).
- A required endpoint is the safer design for a self-hosted app.
- *The biggest concrete risk is Lambda:* every vendor SDK batches in the background, and every vendor
  documents losing data on serverless unless you flush
  ([Langfuse](https://langfuse.com/docs/observability/sdk/overview),
  [LangSmith](https://docs.langchain.com/langsmith/serverless-environments),
  [Braintrust](https://docs.braintrust.dev/sdks/typescript/install-and-instrument.md),
  [Phoenix](https://arize.com/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-using-phoenix-otel)).
- *Borrow the lesson, not the batching:* make `send()` a single awaited `fetch` with a short timeout that
  **never throws** into the host app. That matches Helicone's "not on critical path"
  ([proxy vs async](https://docs.helicone.ai/references/proxy-vs-async.md)).
- Document "await before returning from the handler". If a batch API is added later, also add `flush()`.
- Generate the trace id in the SDK (item 9) so the caller can log it.
- "Never reads or sends API keys" matches Helicone's async logger, which sends provider request and
  response bodies, not keys. State in the spec that the SDK doesn't wrap the provider client, so it can't
  see provider keys.

**8. Claude Haiku judge on one stored trace, on request, through a single route.**
- *Matches a subset of the norm.* Langfuse supports manual evaluate-selected-rows and test-on-sample. The
  automated online rules with sampling, which Langfuse, LangSmith and Braintrust all have, are deliberately
  skipped. That's the right cut for v1.
- *Borrow the consensus score shape:* `name`/criterion, numeric `value` with a fixed range (Braintrust
  uses 0–1), an optional `label`, and `explanation` text. This maps 1:1 to OTel
  `gen_ai.evaluation.result`
  ([events](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-events.md))
  and to Langfuse scores
  ([scores](https://langfuse.com/docs/evaluation/evaluation-methods/scores-via-sdk)).
- Store which judge model and prompt version produced the score.
- Like Langfuse, the judge sees only the one trace's input and output.
- Decide whether re-judging creates a new score or replaces the old one. Langfuse's id+name+date rule
  shows how subtle that gets, so keep it simple: either append-only, or one score per (trace, criterion)
  with upsert.
- Since the dashboard is public and the route calls a paid model, rate-limit or authenticate the judge
  route. None of the vendors expose an unauthenticated judge trigger.

**9. Client-generated IDs and upserts.**
- *Matches the norm.* OTel IDs are client-side, LangSmith recommends client UUIDv7
  ([trace with API](https://docs.langchain.com/langsmith/trace-with-api)), and Braintrust replaces the row
  when an id repeats ([insert logs](https://docs.braintrust.dev/api-reference/logs/insert-project-logs-events)).
- *Borrow:*
  - UUIDv7, which sorts by time and suits indexes and dashboard ordering;
  - Braintrust's semantics: a repeated id fully replaces the row, which makes retries idempotent.
- Spec one guard: an upsert must be refused, or ignored, if the existing row with that id belongs to a
  **different ingest key or app**. Otherwise one app's key could overwrite another app's traces.
- Spec the response: 201 vs 200 for an upsert, and whether the body echoes the id.

**10. Public read-only dashboard with per-app totals.**
- *Differs:* every vendor's UI requires login. Public is fine for a portfolio, and it's a strong
  argument for content-off-by-default.
- Make sure prompt and response text, if stored, either isn't shown publicly or is clearly opt-in per app.
- Never display key hashes. Show only the prefix and suffix.
- *Borrow:* the usual dashboard aggregates are per-app counts, token sums, cost sums (excluding unknown
  cost, with a count of how many were unknown), and latency percentiles. Langfuse, Braintrust and
  LangSmith all compute totals per span, not per trace. With AInakupo's flat model these are the same
  thing.
